## Points

1. **A monitor scaled up next to one of a larger scale had dark edges** (confirmed,
   about 75 % at the edges, 56 % in the corners at scale ratio 2). The bilinear filter
   blended with the transparent outside. The pattern now pads.
2. **Fractional scales lost a row** (confirmed). The scale came from the width only,
   but the compositor cuts the logical width and height off separately: 1280x720 at
   1.3 came out 1280x719, and a click in `-r` lost the row at many more scales. Now a
   scale per axis, and `pixel_at()` floors with an epsilon (702 * (720 / 702.0) is just
   below 720). grim loses the row too, so these tests compare with mwc's `capturec`.
3. **The default save failed on vfat and exFAT** (plausible, then shown with a fake):
   `link()` gives EPERM there. Now `renameat2(RENAME_NOREPLACE)` takes over, which
   doesn't overwrite either. `tests/nolink.c`, an LD_PRELOAD library, fakes such a
   filesystem.
4. **Errors writing to stdout went unnoticed** (confirmed): the path, `-l` and `-v`
   onto a full disk gave status 0. Now status 1 and a message; a saved picture stays.
5. **`-f` replaced what it was given through a rename** (confirmed): a file of mode
   600 came back 644, a symlink became a plain file, a named pipe a file nobody read,
   and `-f /dev/stdout` failed. Now a plain file keeps its mode, and anything else is
   written in place.
6. **Three waits counted the processes only once** (confirmed): `$(shot_count)` was
   expanded when `wait_for` was called. Now functions that count on each call.
7. **The stalled reader test passed without the 5 s cutoff** (plausible): the stuck
   reader's timeout ran out just before clip's. It now outlives clip's timeout.
8. **The lock file test never reached the `.lock` check** (confirmed): `is_socket()`
   already drops a lock file, so the name check is gone. The dead socket the comment
   promised is there now, and failing on it would fail the test.
9. **Nothing checked that `-d` waits** (confirmed). Now timed.
10. **`-v` lacked the commit built**, as the C project rules want (confirmed). Now
    `0.4.3+DATE.TIME.HASH`, `.dirty` for changes not committed, as in mwc.
11. **`-h` said only the right button gives `-r` up** (confirmed); any but the left
    one does.
12. **`-l` and `-v` ignored what came with them** (confirmed), and `-v junk` passed
    because `-v` exited inside the option loop. Now status 2; `-q` is fine with them.
13. **The clipboard's process kept the caller's directory** (confirmed), so a stick
    it was started from could not be unmounted. Now `chdir("/")`.
14. **The clipboard's process kept the capture's buffers and the picture** (confirmed),
    100 MB and more on two 4K monitors, for hours. Now only the PNG stays.
15. **An unchecked strdup of the socket names** (plausible). Now a fixed array.
16. The compositor's stride is taken as it is; one of less than four bytes a pixel
    would make screenShot read past the buffer (plausible).
17. Little endian only: wl_shm's formats are little endian, cairo's native
    (plausible).

## Second round

Four reviewers on the branch's diff at bae0d3a: files, scales, lifetimes and options,
tests. All four points fixed, each with a check that fails without it.

1. **`-f` followed someone else's link** (confirmed with a probe), a regression of
   point 5. In a shared folder without the sticky bit, where `fs.protected_symlinks`
   doesn't help, a planted `shot.png -> ~/.bashrc` got the PNG, and one to nowhere
   created its target. Now only a link of one's own or root's is followed, or one
   that leads to stdout itself (in a container root's shows as nobody's, as
   /dev/stdout in mwc's box). Any other is replaced. `tests/otheruid.c` makes the
   test's own links look like a stranger's.
2. **Two monitors at the same fractional scale were resampled** (confirmed by the
   numbers), a regression of point 2. 1280x720 and 1920x1080 at 1.3 differ in the y
   scale in the fourth place, so one was stretched by 1.0006 and filtered. An output
   off by less than a pixel over its size is now copied as it is, and the picture's
   size comes from where the outputs lie.
3. **`-h` didn't check its write to stdout**, unlike `-v` and `-l`. As in
   digitalClock and displayOff: checked, and `-h` stands alone.
4. **The option tests reached the running session** (confirmed: mwc's box passes
   `WAYLAND_DISPLAY` and the runtime directory through). A regression in the checks
   would have copied into its clipboard or frozen its screen. The tests now set
   `XDG_RUNTIME_DIR` to their own directory and unset `WAYLAND_DISPLAY` before
   anything runs.
